Actionable maintenance finding

Batch cost aggregation uses costes[0] as fallback when not every element is a number (line 333: '? Number(...) : costes[0]'). If mixed numeric/undefined costs are returned across parallel tasks, the reported catalog.bob.coste silently drops all but the first task's cost instead of summing what is available or flagging the gap. The fix is to sum only the numeric elements and store the count of tasks with known costs alongside, so operators can tell at a glance whether the reported figure is partial: replace the ternary with { coste: costes.filter(c => typeof c === 'number').reduce((a,b)=>a+b,0) || null, tareas_con_coste: costes.filter(c => typeof c === 'number').length }.
